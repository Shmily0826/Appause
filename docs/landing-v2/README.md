### 第九轮补修：三条结构缺陷（2026-09-29）

冷评指出三处「浏览器能容错、但语义或打印会坏」的问题，本轮修掉（页高不变，仍为上面四档）：

| 问题 | 修法 |
| --- | --- |
| `<dl>` 里直接放 `<li>`（4 组）——非法嵌套，读屏的关联列表语义是乱的 | 改成 `<dl><div><dt>…<dd></div></dl>`；CSS 选择器 `.perms li` → `.perms > div`（grid 布局保留） |

| FAQ 展开指示用 `content:"+"`，读屏会念「加号」 | 改画两条渐变线（`::before` / `::after` 用 `background` + `rotate`），加减号不再由字符承担 |

顺手修：`<span class="mono">` 是死类（全 CSS 无定义）→ 换成已有样式的 `<code>`；顶栏 `backdrop-filter` 补 `-webkit-` 前缀。

## 每一份都做了什么

`timeline.html` 的改动，来自 [timeline 审计](../landing-reviews/) 的逐条结论：

- **下载区由墨底改纸底**：`2px` 粗墨边框 + 纸底，全页统一浅色。原先唯一的深色区块是「墨底 + 朱红按钮」，正是被否掉的那组气质。
- **补上中段的转化断层**：宽屏加粘性导航条（含常驻下载入口），窄屏加吸底下载条（滚过首屏出现，下载区在视野内时自动让位）。此前 13 屏的手机页面里，下载入口只在首屏和倒数第二屏。
- **发版少改几处、且不会漏掉藏在折叠区里的值**：版本号、versionCode、发布日、体积、SHA-256 收敛到脚本里的 `RELEASE` 对象，页面上所有 `[data-r]` / `[data-apk]` / `[data-release]` 由它填充。**注意边界**：markup 里仍保留 16 处 `v0.5.45` 字面量（4 个下载 `href` 各含两段 URL + 静态兜底文案），JS 生效时会被覆盖，无 JS 时靠它们兜底，所以发版仍需一次全局替换。真正的收益是 `SHA-256`、`versionCode`、体积这些手改容易漏的值不用再手改。
- **补分享与图标**：og / twitter / canonical / favicon / apple-touch-icon。⚠️ 当时 `canonical` 抄的是复制来源 `timeline.html`，把这一版声明成了旧版的重复内容，第七轮才修成自指。
- **无障碍**：加跳读链接；`--ink-faint` 由 `#776f5e`（纸底 4.41:1）压到 `#6b6353`（5.27:1）；SHA-256 展开区触控高度提到 44px；链接列表加垂直内边距。
- **文案精确化**：正文补出「新分组默认 10 秒」；「冷却时间」改为「最长 60 秒，免费与 Pro 的上限相同」。
- **排版**：小节说明行的行宽由 44em 收到 38em；窄屏两张截图改为并排（手机页高从 11236 降到 10057）；纯颜色 `:hover` 全部包进 `@media (hover: hover)`；底部为吸底条留出安全间距。

## `timeline-refined.html` 又改了什么

上一版交付后自审发现的问题，逐条修在第一屏与导航上：

- **首屏大图改用裁切派生图** `images/screenshots/zh/pause-crop.png`（1080×1631）。原图 1080×2400 的内容到第 1543 行就结束，底部 32% 是空白——在 1280 视口渲染成 233×514 时，约 170px 是纯白，产品核心视觉只占图像上部的三分之一。裁切用像素扫描定位内容范围（`scripts/crop-shot.mjs`），原图保留不动，因为 almanac / receipt / catalog 仍在用整屏图。
- **报头与导航条合并成唯一顶栏**。此前两处各写一遍品牌，首屏顶部 64px 内出现两个 "Appause"（实测 `.masthead .brand` top 34、`.navbar .to-top` top 98）。现在一条粘性顶栏装品牌 + 栏目 + 下载；窄屏只留品牌与下载，栏目链接隐藏（由小节标题和吸底条承担导航）。报头原来的 `6px` 墨色上边框移到顶栏保留。
- **顶栏栏目加当前位置高亮**（`aria-current`）。此前 6 个链接是纯静态列表，没有任何「你在哪」的提示。实测滚到「权限与隐私」时该项高亮正确。
- **中文孤字修正**。`text-wrap: pretty` 对 CJK 断行几乎无效（改后末行仍是 3 字），改成**短块用 `text-wrap: balance`**：`规则由你定…` 末行由 3 字变 14 字，`手机上总有那么两三个应用…` 由 4 字变 20 字。
- **小修**：吸底条补 `role="region"`（原来 `aria-label` 挂在没有 role 的 `div` 上，实际无效）；`<summary>` 不再重复声明 `role="button"`；首屏图注去掉「真实的」三字（与项目「不强调真实截图」的约定一致）。

### 第三轮（同一文件）

上一轮改动带出的问题，连同遗留项一起修：

- **窄屏顶栏只留品牌**：原先移动端有两个常驻下载入口（顶栏 40px + 吸底条 48px），加上首屏共 3 处，顶栏 60 + 底栏 68 = 128px（844px 视口的 15%）常驻给外框。现在窄屏隐藏顶栏下载按钮（`≤61.99rem`），下载统一交给吸底条；宽屏保留（宽屏没有吸底条）。实测 390/320 顶栏高 60 → 52。
- **补 `scroll-margin-top: 5.5rem`**：全页此前一条都没有，锚点跳转会把小节的分隔线塞到粘性顶栏下面，标题只是因为 `padding-top` 恰好够高才没露馅。实测跳转后 h2 顶部 137px，顶栏底 52px。
- **`.hero-badges` 不再画 `·`**：320px 下折 3 行时行尾会挂一个点。改成 flex + `gap`，现在折 2 行且行尾干净。
- **跳读链接挪到顶栏下方**：聚焦矩形原来 y 8–52、顶栏底 60，`overlapped: true` 会盖住品牌；现在 y 72。
- **下载区底色用 `--paper-raise`**（浅一档的纸）+ 2px 墨框：全页统一浅色之后丢掉了唯一的重量点，用色阶差找回收尾层次，**不引入任何深色**。
- **小节留白做出轻重**：叙事型（拦截经过、免费与 Pro）上方放松到 `space-6`，表格型（验证台账、权限、常见问题）上方收到 `space-4`。桌面总高 6900 → 6766。
- **序不再是「单独的一段」**：原来是一段无标题、居中、纯文字的过场，是全页唯一既没标签、也没图、也没列表结构的小节。改成左「序」+ 断句／右正文的非对称两栏，加一条栏线呼应台账；断句取自原文第一句，段序按原顺序重排，没有删改任何一句，也没有新增事实性文案。顺带补上了这一级标题（此前 h1 直接跳到「拦截经过」）。
- **加了 print 样式**：隐藏常驻外框，背景与面板转白，`section { break-inside: avoid }`。样张见 `output/landing-review/shots/review/refined-print.pdf`。

### 第四轮（同一文件）

- **序减量并修断行**：断句由 48 字压到 12 字「手指先到了，人还没决定。」（字号下限降到 `1.3rem`，保证 320px 下也是完整一行）；正文减量约 35%，删去与首屏、拦截经过重复的一句；用 Range 逐字量出真实断点后，用 `.nb { white-space: nowrap }` 锁住会被拆开的词（`停顿` / `继续` / `每次` / `判断` / `交还给你`）。
- **`text-wrap` 分工修正**：正文段落原先用 `balance`，会把 3 行摊成等长——每行只占栏宽约 2/3，行尾大片留白，看着像被切断。正文改为 `pretty`（行填满），`balance` 只留给 1 至 2 行的短块。
- **焦点描边修正**：填充朱红的按钮上，朱红描边等于自身底色，可见性只剩 2px 的缝。三个按钮改用墨色描边（墨/纸 15.4:1）。
- **打印修正**：`break-inside: avoid` 从 `section` 改到小组件（`tr` / `details` / 时间轴条目 / 计划栏 / 下载面板 / `figure`），PDF 10 页 → **9 页**；按钮在打印媒体里改白底墨字加边框（浏览器默认不打印背景图形，否则会白底白字）。
- **窄屏截图可读**：`≤560px` 由两列并排改单列、宽度 62%。并排图宽 320px 下 132 → **174**，390px → **217**，560px → **322**。

### 第五轮（同一文件）

- **折叠面板加了展开／收起的缓冲动画**。常见问题与下载区的 SHA-256 说明此前是瞬时开合。现在：
  - 主方案用 `::details-content` 过渡 `block-size`（配合 `:root` 的 `interpolate-size: allow-keywords`，Chrome 131+），展开 260ms 从 0 到 `auto`，**收起同样有收敛过程**。
  - 右侧加号改由两条渐变线画出——`content` 的「＋」「−」之间无法过渡，只能换画法：展开时把竖线收到 0，得到真正的收放动作（`background-size` 过渡）。
  - 通用兜底：展开时答案做 `reveal` 关键帧（淡入 + 上移 0.3em）。不支持的浏览器忽略上面两段，仍有淡入缓冲；完全支持时两者叠加，是「高度展开 + 内容显影」。
  - 降级：`prefers-reduced-motion: reduce` 下过渡与关键帧全部关闭，高度瞬时到位（实测 open 后立刻是 159px）。打印媒体下也关掉动画——否则 `animation-fill-mode: both` 会停在起始帧，把展开过的答案印成空白。
- **实测数据**：展开 59 → 93 → 129 → 142 → 153 → 158 → 159px（约 260ms 逐帧推进）；收起 159 → 125 → 98 → 75 → 65 → 60 → 59。逐帧对照见 `output/landing-review/shots/review/00-faq-animation.png`。
- **顺带移除**了加号 `::after` 里的文本符号，读屏软件不会再念一个多余的「+」；开合状态由 `summary` 上的 `aria-expanded` 播报。
- 标记的对齐是算出来的不是调出来的：盒子高度取 `1.75em`（= 行高），`top` 取 `0.9em`（= 内边距），所以无论标题折成几行，十字都锁在首行中线（320px 下实测两个中心值相同）。

`全部功能免费，Pro 是实验项` / `只有一项权限是必须的，其余都可以不给` / `没有账号，没有广告，没有统计 SDK，也没有云同步`。

三句的共同机制是同一个：**用一句对称、完整、漂亮的断言，把不整齐的事实盖过去。**

| 句子 | 它盖掉了什么 |
| --- | --- |
| 全部功能免费，Pro 是实验项 | ① 比 App 自己的口径还满（`strings.xml` 是「核心功能永久免费，没有订阅或付费版本」）；② 「既然免费为什么还要激活码」这个真问题 |
| 只有一项权限是必须的，其余都可以不给 | **与同一节表格自相矛盾**：电池不设成无限制，在小米上就是「拦截失灵的第一大原因」，那项实际是必需的 |
| Pro 是实验项 | 「实验项」是抽象标签；读者要的是「哪四项」 |

### 页面级的问题比单句更重

六个小节副标题 **100% 是同一种修辞**（平衡的断言句）：否定并列 / 数量对照 / 从 X 到 Y 框架 / 对仗。人类写六节不会六节一个形状。

所以这版不是逐句润色，而是**让形状参差**：删 2 个（三步开始用、分组与记录）、改 3 个（权限与隐私、免费与 Pro、真机验证）、合并 1 个（拦截经过，把「※ 不是示意图」那句并进副标题后删掉）。

### 验收之后又修的两处（同一文件）

评审者指出两条，都核实为真：

**① 左边距被 `padding` 简写吃掉了（P1）**

`.wrap` 用 `padding: 0 1.25rem` 提供左右留白，但 `.hero` 与 `.navbar-row` **写在它后面、同为单类特异性**，而 `padding` 简写会一次性设定四个边 —— 这两个元素的 class 都是「`wrap` + 本类」，于是左右内边距被覆盖成 0。

实测 390px：`h1` / `lede` / 下载按钮 / 品牌 的 left 全是 **0**，同页其他小节是 **20**。1280px 时 left=100（正常应 120），这 20px 缺口被 `max-width: 1080` 的居中余量盖住，**所以桌面上完全看不出来** —— 前九轮的截图都以桌面为主，这是它一直没暴露的原因。

修法：三处 shorthand 改 `padding-block`（`.hero` 基础规则、`@media (max-width:880px)` 里的覆盖、`.navbar-row`）。修后 390px 全部回到 **20**，与全页一致。

> **规则**：容器一旦用 padding 做 gutter，后续任何规则都只能写 `padding-block` / `padding-inline`，写 shorthand 就是埋雷。
> ✅ **线上 `index.html` / `zh.html` 不受影响**：它们的 `.container` 是 `width: min(…, calc(100% - 3rem))` + `margin-inline: auto`，用**宽度**而非 padding 做留白，且 `.hero` 是独立外层元素，没有类叠加。

**② 「暂停界面」改回「暂停页」**

脚本扫 `values-zh/strings.xml` 的 352 条用户可见串：**`暂停页` 11 次、`暂停界面` 0 次**（另有 `暂停屏` 1、`暂停设置` 1），而落地页通篇用 `暂停界面` 16 次。

⚠️ 这是**第七轮我自己引入的偏差**：当时为了消掉「暂停层 / 停顿卡片」这批自造词选了「暂停界面」，却没回头核对 App 到底叫什么。按「用词必须对齐 strings.xml」这条项目规则，改回 `暂停页`。

> 顺带说明：`docs/INSTALL.md` 与 `docs/archive/TEST_REPORT.md` 两条链接**仍是 404**（实测），根因是那批重命名只暂存未推送。**正确做法是提交推送重命名，不要把链接改回根目录路径** —— 改回会在推送之后再坏一次。

**修正**：此前这节写「重组已暂存，推送即愈」是错的。实测暂存区是空的——25 个文件处于工作区删除态（` D`）、`docs/` 下的新文件处于未跟踪态（`??`），索引里根本没有 `docs/INSTALL.md` 这个路径。所以修复需要四步：`git add -A` → `commit` → `git fetch && git rebase origin/main` → `push`。前三步已于 2026-09-29 完成（提交 `57bde20`），**这两条链接在推送后才会真正可用**。

**2. 本地与远端曾经分叉（已修复）**

修复前的真实状态（`git ls-remote` + `git patch-id` 实测）：

- 远端 `main` = `a1e7908f`（`fix: harden accessibility service lifecycle`）+ `3d667e991`（`metrics: weekly snapshot 2026-09-27`）
- 本地 HEAD = `4fb2d96c`，**与远端 `a1e7908` 是同一个补丁**（patch-id 相同：`f679f9b2`）——该提交推上去过，之后本地又 rebase 重写成了孤儿
- 关系是**分叉**（本地独有 1 / 远端独有 2），不是单纯的「落后 1」

⚠️ **此时 `push --force` 会直接冲掉远端的 `3d667e991`（metrics 快照）**。正确做法是 `git fetch origin && git rebase origin/main`——同 patch-id 的孤儿提交会被自动识别丢弃（实测输出 `skipped previously applied commit 4fb2d96`），只重放 metrics 那一个提交。

现已 rebase 完成，关系为**本地领先 1 / 落后 0**，`push` 是 fast-forward，**不需要也不需要 `--force`**。

本地那个坏掉的 `origin/main` 引用会让 `git status` 谎报「领先 61 提交」，判断远端状态一律用 `git ls-remote` 或 `git log --oneline origin/main..HEAD`。
