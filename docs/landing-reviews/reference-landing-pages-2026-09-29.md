# 竞品落地页实测 + 首屏三处问题（2026-09-29）

对象：`docs/landing-v2/timeline-humanized.html`
方法：本地 Chromium（1280×900，headless）实测本页与 6 个竞品页；截图存 `output/landing-review/shots/refs/`。

## 一、首屏三处问题（实测数据）

### ① 顶栏导航看不出来能点

| | 本页 | one sec | Opal | Linear | Raycast |
| --- | --- | --- | --- | --- | --- |
| 字号 | **12.8px** | 17px | 16.6px | 13px | 14px |
| 字重 | **400** | 500 | 500 | 400 | 500 |
| 颜色 | `ink-soft` 灰（6.53:1） | 纯白 | 纯白 | `#8a8f98` | `#9c9c9d` |
| 纵向内边距 | **5.6px** | — | 12px | 0 12px | 12px 8px |
| 命中高度 | **25px** | 26px | **51px** | 32px | **41px** |
| 静止态可点线索 | **无**（`border-bottom` 透明，只在 hover/current 出现） | 字重 + 间距 | 字重 + 内边距 | 32px 胶囊 | 41px 胶囊 |

结论：本页导航是**全页唯一比正文（16px）还小的一处文字**，字重 400、灰色、25px 命中高度、静止态零线索——所以读起来像图注而不是导航。竞品最少的做法也是「与正文同级字号 + 字重 500 + 38–51px 命中高度」。

### ② 顶栏与正文之间的留白偏大

| 站点 | 顶栏底 → 首屏内容顶 |
| --- | --- |
| **本页** | **120px** |
| one sec | 111px |
| Opal | **84px** |
| ScreenZen | **~85px** |
| Linear | 199px |
| Raycast | 278px |

本页 120px 来自 `.hero { padding-block-start: var(--space-6) }`（7.5rem）。**绝对值不算离谱**（Linear / Raycast 更大），差别在**对照物**：它们那片留白上方是深色带或有底色的顶栏，本页顶栏与纸面同色、导航又弱，于是 120px 读起来是"空"，而不是"呼吸"。两条路：把留白收到 72–84px，或让顶栏有颜色分层。

### ③ 右侧图偏小、和左栏不成比例

| 站点 | 首屏产品视觉 | 首屏文字栏宽 | 图 / 文 |
| --- | --- | --- | --- |
| **本页** | **231 × 348** | 611px | **0.38 : 1** |
| one sec | 450 × 675（+ 230×510 装饰列） | 360px | **1.25 : 1** |
| ScreenZen | 440 × 609 | ~360px | **1.22 : 1** |

根因是本页的 `.hero-shot img { width: min(330px, 86%) }`：右栏只有 269px 宽，86% = 231px，被 `330px` 上限和百分比两道一起压住。竞品是**图比文字栏还宽**；本页正好倒过来。修正方向：右栏给到 380–440px 固定区间、图宽放开到 100%，让图/文 ≈ 0.75–1.0。

## 二、6 个竞品页面结构（按页面顺序）

| 站点 | 首屏之后依次是 |
| --- | --- |
| one sec | 数据证明（3000 years / 57% / 2h，带文献角标）→ 机制（Interruptions 九种）→ 再一段收益 → 功能 → 集成 → 媒体 logo 墙 → 大学研究 → **Why one sec?（3 条）** → 评分与 10 条评价 → FAQ（6 条）→ 文献列表 → 末屏 CTA |
| Opal | 痛点数据（5–6 小时）→ 四个 ® 功能 → 成就徽章墙 → 平台可用性 → 省时数字（1h23m/1 月/6 年）→ 三个百分比（94%/93%/90%）→ Pro 卖点 → 10+ 张用户证言卡 → 社区入口 |
| ScreenZen | 评级 + 媒体背书 → 三个平台下载按钮 → 「用户每周省回 3 小时」→ 功能 → 差异点 → CTA |
| Linear / Raycast | 首屏 → 客户 logo → 产品演示图 → 功能分组 → 定价 → 底部 CTA |

**共同点（本页已具备或部分具备）**
- 首屏 = 一句短标题 + 一到两句副标题 + 1 个主 CTA（+ 可选次 CTA）。没有别的东西。
- 数字证明紧跟首屏，且**带来源或样本量**（one sec 每条数字挂文献；Opal 标注 N=300,000）。
- 「讲机制」用 2–4 组、每组一图一句，**不写时间轴**。
- FAQ 一律放**页面最后**，答案 1–3 句。

**共同点（本页缺的）**
- **首屏附近的社会证明**。ScreenZen 把「30K+ 评分 ★4.8 / Featured in The New York Times」放在**标题上方**。本页没有，而且 `PRODUCT.md` 明确不许编造证言与效果数据 → 只能继续用第三方可核信号（MIT 开源、真机验证、Release 下载量）。
- **数字化的结果**。竞品首屏后第一屏几乎都是数字；本页第一个数字出现在第 6 节（1.8 秒 / 291 毫秒），且是技术数字而非收益数字。这是本页结构上最大的空档。

**本页独有、竞品都没有的**
- 权限逐项说明（6 行表）、真机 logcat 验证台账、APK 校验值与 versionCode、安装三步。竞品把这些压缩成一句隐私承诺或一条 FAQ。

## 三、哪些文案没必要（按"删了不影响理解"排序）

1. **首屏 6 个 badge**：`公开测试版 v0.5.45 / Android 8.0+ / MIT 开源 / 数据只存本机 / 日常使用不联网 / 不统计你的使用行为`。后三项是同一件事的三种说法（数据不出本机），实测在 1280px 已经折成两行。**建议留 3 个**：`公开测试版 v0.5.45` `Android 8.0+` `MIT 开源`，把隐私那句合并成一条。
2. **首屏图注后半句**「上面写的是：给自己几秒，再决定是否继续。」——图里正显示着这句话，属于复述。留「真机上的暂停页。」即可。
3. **「一次拦截的经过」的六个时间戳**（T+0.00s / 紧接着 / 倒计时 / 二选一 / T+0.29s / T+1.8s）：竞品讲机制用 2–4 组。建议压到 3 条（拦下 → 冷却与选原因 → 回桌面/继续），把 291ms、1.8s 这些留给真机验证表。**这是深度内容，不是首访者需要的信息。**
4. **真机验证表的「方法」列**：`logcat（reason=homekey）`、`WindowManager 状态记录`、`setHideOverlayWindows`——对开发者是可信度来源，对普通读者是噪音。建议整张表收进 `<details>`，标题写「怎么验的（四条）」。
5. **`versionCode 97` / 包名 / SHA-256**：保留（可核），但都在下载区且已折叠，不动。
6. **权限表的「用途」列偏长**：`使用情况访问` 那条 62 字，是表里最长的。竞品同类信息一句话。可压到「不开的话，打开最近任务可能为你没开的应用弹出暂停页」。

**不建议删的**
- 权限表本身、真机验证、MIT 开源、`日常使用不联网`。这是本页唯一的信任资产——竞品用证言和数据填这块，本页只能用可核事实填，删了就没有东西替代。
