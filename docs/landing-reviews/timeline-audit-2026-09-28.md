### 序：减量 + 断行

评审者指出「文字太多、信息密集、文字切分不好」（附了截图，左栏「回／过神来」、右栏「很多时／候」都被拆开）。处理：

- **断句压到 12 字**：48 字 → 「手指先到了，人还没决定。」，并把字号下限降到 `1.3rem`，保证 **320px 下也是完整一行**，从根上不给浏览器在词中间切的机会。
- **正文减量约 35%**（158 字 → 102 字）：删去与首屏、拦截经过重复的一句。
- **`text-wrap` 分工修正**：原先 `.preface-body p` 用的是 `balance`，而 `balance` 会把 3 行摊成等长——每行只占栏宽约 2/3，行尾大片留白，看起来像被切断。正文改用 `pretty`（行填满），`balance` 只留给 1 至 2 行的短块（断句、小节说明、图注）。
- **逐字量断点，再锁词**：用 Range 逐字取位置、按 `top` 分行，量出真实断点，再用 `.nb { white-space: nowrap }` 锁住会被拆开的词（`停顿` / `继续` / `每次` / `判断` / `交还给你`）。1280 与 992 下现在完全无词内切分，断点落在标点或锁定词之前。

> 说明：中文没有词边界，浏览器可以在任意两个汉字之间断行，**换一个视口宽度断点就会变**。所以这里能做的是：显示级短句压到一行、正文减量、以及用 `.nb` 锁住已观测到会裂开的词。不追求所有宽度下都无词内断行（做不到，也没有必要——中文排版本来就允许在汉字间断行）。

## 八、第五轮：折叠面板的缓冲动画

评审者要求「加一个缓冲动画而不是直接打开」（附常见问题截图）。研究对象是全页两处 `<details>`：常见问题六条、下载区的 SHA-256 校验值。

关键约束有两条：

1. **原生 `<details>` 无法直接过渡高度**。`open` 属性一加，元素高度立刻从折叠态跳到展开态。能过渡的只有 `::details-content` 这个伪元素，且需要 `interpolate-size: allow-keywords` 才允许把长度过渡到 `auto`。
2. **`content` 属性无法过渡**。原来的加号是 `summary::after { content: "+" }`、展开时换成 `"−"`，两个值之间没有中间态，只能瞬时切换。

### 实现

| 层 | 做法 | 作用 |
| --- | --- | --- |
| 高度 | `details::details-content { block-size: 0; overflow: hidden; transition: block-size 260ms, content-visibility 260ms allow-discrete }`，展开态 `block-size: auto`；`:root` 加 `interpolate-size: allow-keywords` | 展开与收起都有 260ms 的高度过渡 |
| 标记 | 加号改由两条 `linear-gradient` 画出（横线 + 竖线），展开时 `background-size` 把竖线收到 `1.5px 0` | 「＋ → －」真正过渡了（220ms），不再是瞬时换字 |
| 内容 | `details[open] > p / > code` 加 `reveal` 关键帧：`opacity 0→1`、`translateY(-0.3em)→0` | 全浏览器的通用兜底，也给支持的浏览器叠一层显影 |
| 降级 | `prefers-reduced-motion: reduce` 下过渡与关键帧全部关闭 | 实测 open 后高度立刻是 159px（与稳定态相同） |
| 打印 | 打印媒体里 `animation: none` | 否则 `animation-fill-mode: both` 会停在起始帧（`opacity: 0`），把展开过的答案印成空白 |

`::details-content` 与 `interpolate-size` 都是渐进增强：不支持时那两段整段失效，页面退回「瞬时展开 + 淡入」，不会坏。同一处也顺带移除了标记里的文本符号——读屏软件不再多念一个「+」，开合状态由 `summary` 上的 `aria-expanded` 播报（该同步脚本原本就有）。

### 实测证据

用 CDP 把动画放慢 50 倍后逐帧截取（`scripts/_verify-accordion.mjs`）：

```
展开：59 → 93 → 129 → 142 → 153 → 158 → 159px      （约 260ms 逐帧推进，不是一次到位）
收起：159 → 125 → 98 → 75 → 65 → 60 → 59px
中间帧：约 14ms 时 65px、44ms 时 79px、84ms 时 91px、134ms 时 98px
reduce 模式：过渡 = none，p 上动画数 = 0，open 后高度即时 159px
打印媒体：展开的 p 为 opacity 1 / animationName none / 高度 84px（可见）
```

逐帧对照图：`output/landing-review/shots/review/00-faq-animation.png`。

标记的对齐是算出来的而不是调出来的：盒子 `top: 0.9em`（等于 `summary` 的 `padding-top`）、`height: 1.75em`（等于行高），所以十字恒定锁在首行中线；320px 下标题折行时实测两个中心值同为 `28.968px`，加号仍留在第一行。

第五轮验收：四档 0 溢出 / 0 断图 / 0 报错；对比度、焦点描边、标题层级均无回归；打印 PDF 仍为 9 页。

### 结论

**这是这个页面最扎实的部分。** 它不像营销文案，像一份文档：291 ms、1.8 秒、1–60 秒、365 天、窗口类型 2032、`canRetrieveWindowContent = false`、`reason=homekey` 全是可核的数字与常量；FAQ 主动回答「这是家长控制软件吗？」并写明「不适合用来监控别人的设备」；真机表格下面那句「以上是有限验证记录，覆盖面到不了所有机型与系统版本，不能当作全设备质检报告」在落地页里属于罕见的诚实。

### 1（最重要）同一个东西有好几个名字，其中一部分 App 里根本不存在

对照 `app/src/main/res/values-zh/strings.xml` 里用户可见的用词：

| App 内（用户装完会看到） | 落地页在用 |
| --- | --- |
| **冷却**（21 次：`冷却时间`、`打开前冷却 %d 秒`、`冷却规则`、`badge_pause`） | 冷却（8 次） |
| **暂停**（15 次：`暂停页`、`暂停设置`） | 暂停界面（5）、暂停层（8）、停顿卡片（2） |
| 无此词 | **冷静期**（2）、**停顿**（3）、**倒计时**（9） |

落地页给核心机制造了 6 个说法：冷静期 / 停顿 / 倒计时 / 冷却 / 冷却时间 / 冷却规则。给暂停这一屏造了 3 个：暂停界面 / 暂停层 / 停顿卡片。

其中**「冷静期」是最没有存在理由的一个**：App 里没有，且和同一页的「停顿」完全同义。首屏「加一道看得见的冷静期」与序里「加一段等得了的停顿」指的是同一件事。

**建议（不必强行统一成一个词，但要分层）：**

- 体验层用**「停顿」**，但**第一次出现时锚定到 App 里的名字**：「在这些应用前面加一段停顿（App 里叫它『冷却时间』）」。读者装完 App 不会找不到词。
- **删掉「冷静期」**，两处都换成「停顿」。
- **「冷却」只留在引用设置项的地方**（「冷却时间：最长 60 秒」），别在叙述里当动词。
- **「暂停层」是窗口实现的说法，不是用户看到的东西。** 见用户的段落里统一「暂停界面」，把「层」留在技术说明那一句里。

### 2 「试用」和「不收费」在互相打架

- Pro 栏标题：「Pro（实验功能）」
- 说明：「每台设备可自愿开启一次 **7 天 Pro 试用**；试用结束后…申请**免费永久码**」
- FAQ：「Pro 收费吗？**不收费**。」

「7 天试用」在中文里强烈暗示「试用期之后要付钱」，紧接着又说「不收费」，读者会怀疑这是先钓后收。而且**页面没写试用到期后会发生什么**（真实后果是 Pro 的四项功能关闭、已有分组继续拦截、数据不删）。不写清楚，读者只能往坏处猜。

**建议**：把「试用」改成「**体验**」，并把结果直接写出来，例如「先开 7 天体验；到期后 Pro 的四项功能关闭，已有分组和统计不受影响。想要继续用就申请一个免费永久码。」

另外 h2「核心免费，Pro 可选」里的「可选」同样在暗示付费，建议改「**全部功能免费，Pro 是实验项**」或「免费与实验功能」。

### 4 无障碍服务出现了 4 次，从没解释过它是什么

### 顺手修了一个前三版都有的交互 bug

**滚回页面顶部后，最后高亮的那一项不会清除。** 实测（`_check-current2.mjs`）：

```
firstvisit  滚到60% ·怎么装 ·权限与隐私 ·免费与 Pro ·拦截经过 ★真机验证 ·常见问题
firstvisit  回顶部 ·怎么装 ·权限与隐私 ·免费与 Pro ·拦截经过 ★真机验证 ·常见问题   ← 没清掉
refined     同上（前三版都有）
```

根因：滚动高亮只在小节「进入」判定带时刷新（`if (e.isIntersecting) setCurrent(...)`），**没有任何小节在带内时没人去清**，旧值就留着。

改法：维护一个「当前在带内」的集合，每次变化后按文档顺序取第一个在带内的小节；集合为空就 `setCurrent(null)`。同时把小节列表从 `Object.keys(byId)`（顺序 = 导航顺序）改成 `document.querySelectorAll('main section[id]')` 再按导航过滤，保证是 DOM 顺序。

修后实测：顶部无高亮 → 怎么装 → 权限 → 免费 Pro → 拦截经过 → 常见问题 逐段正确 → 回到顶部清除。

## 十五、第十二轮：FAQ 重做（仍落在 `timeline-firstvisit.html`）

评审者指出两点：「这是家长控制软件吗？」该删，以及要补一条「为什么不能直接开通 Pro」。

### 为什么那道题该删

不只是「写得差」。它是一道**防御性问题**：读者进来时并没有这个念头，把它写成 FAQ 标题，等于替他树立一个他本来没有的联想。同时它的答案（「Appause 是给你自己用的」）与「序」里的「要不要继续，一直是你自己说了算」是同一句话，属于纯重复。而 FAQ 是全页最可能被通读的一块，用 1/7 的位置挡一个没人提的问题，是浪费。

定位本身不能丢（`PRODUCT.md` 明确写了它「不是家长控制 / 企业管理 / 安全产品 / 监控工具」），所以改成正向陈述挪进**权限与隐私**的引言，那里正好是读者担心「会不会有人从别处控制我」的位置：

> 它也没有任何远程管理功能：规则只能由这台手机的主人设置，不会有人从别处改它。
