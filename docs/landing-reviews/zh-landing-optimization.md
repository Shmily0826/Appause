# zh.html 落地页优化建议

> 只读审计，未修改源码。以下按优先级排序。

## 1. 首屏 CTA 权重偏低，转化路径不够聚焦
- 主按钮与次按钮在同一视觉层级里靠得较近，`.button-secondary` 边框较淡，首屏容易让用户不确定先点哪。
- 建议：主 CTA 增大字号/内边距或加微弱底色区块；次按钮在移动端可降为文字链接或更轻描边，减少首屏决策噪音。

## 2. 移动端菜单只有“开”，没有明显的“关”
- `.nav-toggle` 当前为固定汉堡图标，`.nav-links` 打开后未切换为关闭图标，也未提供显式关闭按钮。
- 建议：在 `nav-links` 打开时切换 toggle 的 SVG 为“×”，或追加独立关闭按钮；同时给 `.nav-links.is-open` 加明显背景/阴影，让菜单层有“浮层感”。

## 3. Pro 文案区缺少下一步引导
- Pro 区已说明试用/授权规则，但读完没有明确的行动按钮，用户需要回顶部或继续滚动才能继续。
- 建议：在 Pro 区末尾加一个上下文按钮，或在 FAQ 的“Pro 是收费的吗？”答案末尾补一个轻量 CTA。

## 4. 权限说明区块可视层级可再拉开
- `.permission-row` 三段信息密度接近，状态标签、标题、说明在视觉上容易混在一起。
- 建议：给“必需 / 建议开启 / 部分机型备用”加不同语义色或图标；中间标题的字重可以再拉开一点。

## 5. 中文标题的 line-height 仍有微调空间
- 已有 CJK override，但 `h1` 在媒体查询里回退到 `line-height: 1.06`，部分 Android 中文字形 taller 时可能显挤。
- 建议：针对移动端给 `h1 / h2` 设一个最小 `line-height: 1.15 ~ 1.25` 的安全值；必要时调整 `max-width` 单位或关键标题后用 `<wbr>` 避免标点独占一行。

## 6. 信任卖点“日常使用不联网”藏得较深
- 该段放在 `.trust-note` 里，需滚动到“权限与隐私”底部才看到，对侧载 APK 用户是重要决策信号。
- 建议：在 Hero 区或下载面板里补一句极简信任徽章，如“本地优先 / 日常不联网”。

## 7. 下载面板次级信息对比度偏保守
- `.install-facts` 在深色面板里 label 与正文对比阶梯偏小，小屏阅读时容易扫混。
- 建议：label 与正文拉开更明显的对比，或 label 用更浅的蓝灰/灰，正文保持高亮。

## 8. 底部下载链接区缺少版本一致性提醒
- 页面上多个下载入口指向 `v0.5.45`，但 `.download-links` 里“查看公开测试版”没有版本提示。
- 建议：在该链接旁补一个静态版本号文本，方便后续一瞥核对。

## 9. 可访问性细节
- `.nav-toggle` 缺少 `aria-controls`，`nav-links` 缺少 `id`，屏幕阅读器不易建立关联。
- `details/summary` 的 `summary` 缺少 `aria-expanded`，部分读屏软件不会播报展开状态。
- `.button` 缺少统一的 `:focus-visible` 样式，键盘导航时的焦点反馈不够稳定。

## 10. 缺失社会证明/信任信号
- 落地页缺少第三方信号，如 GitHub stars / release 下载量 / 评测引用。
- 建议：在 Hero 区或下载区加一行极简证据（icon + 文字即可），不喧宾夺主。
