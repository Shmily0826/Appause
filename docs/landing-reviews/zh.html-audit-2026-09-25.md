# zh.html 优化建议

> 仅整理建议，未修改页面源码。后续可按优先级逐步实施。

## 一、维护性与信息准确性（高优先级）

### 1. 版本号与下载链接硬编码在 5 处，后续发版容易漏改
- **出现位置**
  - 顶部导航 `.nav-download`
  - Hero 主按钮
  - 产品区 CTA `.tour-cta`
  - Download panel 主按钮
  - Download links 的 GitHub tag 链接
- **风险**：下次发版时只要漏一处，页面就会出现“下载 v0.5.45”和“查看 v0.5.45”不一致。
- **建议**：把版本号提取为单一真实源。例如在 `<head>` 里加一个 `<meta name="appause-version" content="0.5.45">`，或一个全局 JS 常量 `const VERSION = '0.5.45';`，然后让这 5 处引用它。人工改版时只改一个值。

### 2. “使用情况访问权限”的落地描述可能与当前实现不一致
- **位置**：`#privacy` 区块的权限说明 + FAQ「为什么有时候通知也会触发暂停？」
- **当前文案**：把“使用情况访问权限”描述为可选，且能“通过系统本机记录确认前台应用，减少误触发”。
- **项目记忆里的实际状态**：v0.5.24 以后已**信任无障碍事件本身**，不再拿 `getForegroundPackage()` / 使用情况日志当门控，因为它在 HyperOS 上已被证实不可信。
- **风险**：用户按落地页文案去开“使用情况访问权限”，预期是“减少误触发”，但实际代码里该权限并不承担这个核心作用，用户开启后若仍有误触发会产生困惑。
- **建议**：把该权限的描述从“减少误触发”调整为更贴近现状的表述，例如“用于在部分机型上辅助识别前台应用；Appause 的核心判定仍基于无障碍事件”。

### 3. 外部镜像链接携带 token，建议集中管理
- **位置**：`download-links` 里的蓝奏链接 `https://shmily0826.lanzoup.com/b01eunt29a&t=...`
- **风险**：token 过期或更换时需要手动找这一处。虽然只有一处，但建议与版本号一起放到“单一真实源”里维护。

## 二、可访问性（中优先级）

### 4. 移动端菜单按钮缺少 `aria-controls`，导航缺少可关联 ID
- **位置**：`.nav-toggle`（约 1231 行）和 `.nav-links`（约 1238 行）
- **现状**：按钮有 `aria-label="菜单"` 和 `aria-expanded`，但**没有 `aria-controls`**；`nav-links` 没有 `id`。
- **建议**：给 `.nav-links` 加 `id="primary-nav"`，按钮加 `aria-controls="primary-nav"`，让屏幕阅读器能建立显式关联。

### 5. 移动端菜单关闭时，链接仍可能被辅助技术聚焦
- **现状**：关闭状态用 `display: none` 隐藏。部分辅助技术仍能“穿透”读到里面的链接。
- **建议**：关闭时额外加 `inert` 属性（现代浏览器支持良好），或至少 `hidden` 属性，确保内容对 AT 不可见且不可聚焦。

### 6. 多处使用非标准字重值，跨平台一致性一般
- **位置**：`font-weight: 720`、`690`、`640`、`720` 等（约 159、179、248、260、267、296… 行）
- **现状**：这些值不在标准的 100–900 阶梯内，部分系统/浏览器会静默回退到最近有效值（如 700/600），导致字重和你设计时看到的略有偏差。
- **建议**：统一改为标准值：`720→700`、`690→700`、`640→600`、`720→700`。视觉差异极小，但跨平台更稳。

### 7. 建议做一次颜色对比度实测
- **风险点**：`--color-ink-soft: oklch(47% 0.035 258)` 用于正文/说明文字（如 `.hero-intro`、`.section-intro`），在浅底上可能略偏灰。
- **建议**：用 DevTools 的 Contrast Checker 实测一下，确保正文至少 4.5:1，大标题至少 3:1。如果不足，把 `--color-ink-soft` 的 lightness 从 47% 提到 50%–52%。

## 三、性能与交互细节（低优先级，锦上添花）

### 8. 按钮 hover 上浮在触摸设备上可能“粘滞”
- **位置**：`.button:hover { transform: translateY(-2px); }`（304 行）
- **现状**：移动端点击后，`:hover` 状态可能保持到下次点击别处，按钮看起来一直浮着。
- **建议**：用 `@media (hover: hover)` 包裹 hover 效果，或加 `@media (pointer: coarse)` 关闭位移，保留点击反馈即可。

### 9. FAQ `details` 展开/收起无过渡动画
- **现状**：点击瞬间切换，略显生硬。
- **建议**：如果想加动画，可以用 `grid-template-rows: 0fr → 1fr` 或 `max-height` 的 CSS trick；但 `details` 动画 traditionally tricky，如果追求稳定，保持现状也完全可接受。

### 10. 外部下载域缺少 `preconnect`
- **现状**：GitHub Releases、蓝奏都是外部域，首次下载时会多一次 DNS + TLS 握手。
- **建议**：在 `<head>` 加：
  ```html
  <link rel="preconnect" href="https://github.com" />
  <link rel="preconnect" href="https://shmily0826.lanzoup.com" />
  ```
  收益不大，但零成本。

## 四、文案与结构微调（可选）

### 11. Pro 试用/授权描述可以更精炼一致
- **当前在 Pro 区和 FAQ 里重复了较长的同一段话**。可以考虑：
  - Pro 区保留完整说明；
  - FAQ 里改成一句：“公开测试阶段不收费。试用到期后，可在「设置 → 反馈」申请免费永久授权码。”
- 这样减少重复，也避免两处文案万一不同步。

### 12. 移动端导航展开时没有遮罩，背景可滚动
- **现状**：菜单展开时，`.nav-links` 绝对定位覆盖在内容上方，但页面 body 仍可滚动。
- **建议**：展开时给 `body` 加 `overflow: hidden`，或加一个半透明遮罩层。提升体验，也避免菜单打开时误触底层链接。

---

## 总结：最值得做的 3 件事

| 优先级 | 改动 | 原因 |
|--------|------|------|
| **P0** | 版本号/链接 token 单一真实源 | 发版维护安全，避免漏改 |
| **P0** | 修正“使用情况访问权限”文案 | 避免用户对权限作用产生错误预期 |
| **P1** | `nav-toggle` 加 `aria-controls` + `nav-links` 加 `id` | 可访问性合规，成本极低 |
